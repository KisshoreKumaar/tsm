# Security

AEGIS is a single-tenant lab tool. It assumes a trusted operator on a trusted host and does not try to be an
internet-facing service.

## Authentication and authorisation

- Bearer tokens from configuration (`AEGIS_API_TOKEN`, `AEGIS_IDENTITIES`); each identity has one role.
- Permissions: `read`, `ingest`, `investigate`, `ai.use`, `respond.recommend`, `respond.approve`, `respond.execute`,
  `rules.draft`, `rules.approve`, `tuning.draft`, `tuning.approve`, `reports.draft`, `reports.finalize`,
  `settings.manage`, `llm.configure`, `audit.export`.
- Every API route declares exactly one guard; `tests/core/test_rbac_matrix.py` walks every route × role on each run.
- `AEGIS_TWO_PERSON=true` stops the same person approving or executing their own response, rule, tuning change or
  report.
- Tokens travel only in the `Authorization` header. The browser keeps the token in memory: never in storage, cookies
  or URLs.

## What the AI can and cannot do

- AI output is never authoritative. Claims without a valid evidence citation are downgraded or dropped.
- The agent can only draft proposals. Applying one re-checks the human's permission and the target revision, then
  calls the same domain service a manual action would, under that human's identity, in one audited transaction.
- Approve, execute, activate, disable, retire, tuning approve/revert, report approve/mark-submitted, provider
  settings, tokens and audit actions are human-only and have no proposal type (enforced by an assertion and a test).
- Prompt injection: event text is treated as data inside a delimited block, scanned (INJ-001), quoted in stories, and
  never followed. Output that repeats instruction-like text is dropped. Proposals drafted while injection was present
  are flagged and need an extra acknowledgement.

## Secrets

- Provider API keys are encrypted with AES-GCM using a key derived from `AEGIS_SECRET_KEY` (separate from the audit
  key), stored only as ciphertext, and never returned: the API exposes `key_set` and the last four characters.
- Audit bodies reject secret-like keys. Error responses never echo submitted values or stack traces.
- `.env` is generated by `make init-env` and is git-ignored. No secret is baked into a container image.

## Network posture

- The only outbound calls go to LLM endpoints an admin configured. Everything else — response actions, CERT-In
  reports — is simulated or produced as a file for a human to send.
- Provider URLs pass an SSRF guard: http(s) only, no credentials in the URL, no redirects, link-local, loopback,
  metadata and multicast addresses rejected, with an optional host allowlist (`AEGIS_LLM_ALLOWED_HOSTS`).
- Tests cannot open sockets at all: `backend/conftest.py` blocks them, and a test keeps the reports package free of
  network imports.

## Hardening in the app

- Security headers on every response, a per-identity rate limit, body-size limits (with a larger cap for event
  batches), strict JSON parsing, and Pydantic models with `extra="forbid"`.
- Regular expressions in rules and watch signals are restricted (no backreferences, lookarounds or nested unbounded
  quantifiers) and capped in length, because Python's `re` has no timeout.
- SQL is always parameterised; the only dynamic SQL fragments come from fixed allowlists of column names.
- The audit chain is verified at startup and by `make verify-audit`; a tampered chain stops the app.

## Known gaps and assumptions

- **No TLS and no reverse-proxy auth in the box.** Bind to loopback (the compose file does) or put it behind a proxy
  you control.
- **Single tenant.** There is no per-tenant isolation, and any authenticated identity can read all incidents.
- **The demo Ollama endpoint is public and unauthenticated.** Restrict it to your own addresses or tunnel it;
  redaction is on by default for it, but evidence still leaves the machine in plaintext HTTP.
- **The CERT-In template is UNVERIFIED** until checked against the official directions.
- SQLite suits a single-node lab; concurrent writers are serialised by design.
- Containers are unverified: Docker was not available on the build machine.

## Reporting

This is a hackathon prototype. If you find a problem, raise it with the team before pointing the tool at anything
that is not synthetic or an authorised lab.
